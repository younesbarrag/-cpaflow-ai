# Proposal - KAN-15: Enregistrer un clic et rediriger vers l'offre

## 1. Summary

Add a public tracking redirect endpoint that resolves a tracking link by code, verifies the related Campaign is active, records the click with privacy-safe visitor metadata, and redirects to the Offer destination URL. Click persistence failure must not block a valid redirect.

## 2. Problem

KAN-14 generates tracking links but provides no public endpoint to visit them. Affiliates need a functional redirect that records measurably when a visitor clicks a tracking link. The redirect must work for any valid active link without requiring authentication, while protecting visitor privacy and maintaining redirect reliability.

## 3. Objectives

- Resolve a TrackingLink by its unique code from a public URL.
- Verify that the related Campaign is active before redirecting.
- Record a click with privacy-safe metadata (hashed IP, User-Agent, Referer, UTM parameters).
- Redirect the visitor to the canonical Offer.destination_url.
- Ensure click persistence failure never blocks a valid redirect.
- Return 404 for unknown codes and inactive campaigns without leaking state.
- Validate destination URL safety before redirecting (http/https only).
- Cover behavior and persisted state with Pest feature tests and Postman/Newman verification.

## 4. In Scope

- Additive `tracking_clicks` migration.
- `TrackingClick` model and factory.
- `TrackingLink::clicks()` and `TrackingClick::trackingLink()` relationships.
- `RecordTrackingClickAction` for click persistence with best-effort failure handling.
- `IpHasher` service for purpose-separated HMAC-SHA256 IP hashing.
- `RedirectTrackingLinkController` for the public redirect endpoint.
- Destination URL safety validation (FILTER_VALIDATE_URL, scheme, host).
- Public `GET /t/{code}` route in `routes/web.php`.
- Pest feature coverage, Postman/Newman collection, and final technical documentation.

## 6. Dependencies and Compatibility

- Existing `users`, `offers`, `campaigns`, and `tracking_links` tables from KAN-8 through KAN-14.
- Existing `TrackingLink`, `Campaign`, `Offer` models and their relationships.
- Existing `CampaignStatus` enum with `draft`, `active`, `suspended`.
- Existing `Offer.destination_url` (VARCHAR 2048).
- Existing `url('/t/' . $code)` URL pattern generated by KAN-14.
- Laravel `APP_KEY` environment variable used to derive a purpose-separated HMAC key.

The migration is additive. It creates only the `tracking_clicks` table and must not alter or drop existing data or schema.

## 7. Key Decisions

| Decision | Outcome |
|---|---|
| Public route location | `routes/web.php` — no `/api/v1` prefix, no `auth:sanctum` |
| Route name | `tracking.redirect` |
| Campaign status check | Active Campaign proceeds; draft or suspended returns `404` |
| Unknown code | `404` — no state leak |
| Inactive campaign | `404` — identical to unknown code, no state leak |
| IP privacy | HMAC-SHA256 with purpose-separated derived key from `APP_KEY`; raw IP never stored |
| Click failure strategy | Best-effort synchronous with exception logging; redirect always proceeds |
| Redirect HTTP status | `302 Found` |
| Destination URL safety | Defense-in-depth: `filter_var(FILTER_VALIDATE_URL)`, scheme http/https (case-insensitive), non-empty host |
| UTM parameters | Read from query string, truncated to max lengths, nullable |
| User-Agent / Referer | Read from request headers, truncated to max lengths, nullable |
| Queue infrastructure | Not used — synchronous best-effort action is sufficient |
| Click timestamp | `created_at` is the authoritative click time (synchronous recording) |

## 8. Risks and Mitigations

| Risk | Mitigation |
|---|---|
| Click persistence failure blocks redirect | Try-catch around click recording only; exception logged; redirect always proceeds |
| Raw IP stored accidentally | Purpose-separated HMAC-SHA256 hashing service; raw IP never touches the model |
| Malicious destination URL (javascript:, data:) | Defense-in-depth: FILTER_VALIDATE_URL + scheme + host check before redirect |
| Oversized headers cause DB failures | Multibyte-safe truncation at configured max lengths before persistence |
| Campaign status leaks through differential responses | Unknown code and inactive campaign both return `404` |
| HMAC key compromise affects other systems | Purpose-separated derived key using hash_hmac context string |
| N+1 on TrackingLink→Campaign→Offer | Bounded eager-loading query set with `with(['campaign.offer'])` |
| IPv6 normalization inconsistency | `inet_pton()` + `inet_ntop()` produces canonical representation |
| TrackingLink with missing Campaign or Offer | Null-safe property access; missing relation returns `404` |

## 9. Success Criteria

- Valid code with active Campaign records one click and redirects to Offer.destination_url.
- Redirect uses `302 Found` status.
- `created_at` represents the recorded click time.
- Unknown code returns `404`.
- Draft Campaign returns `404`.
- Suspended Campaign returns `404`.
- Missing Campaign relation returns `404`.
- Missing Offer relation returns `404`.
- No authentication is required.
- Raw IP is never stored in the database.
- IP hash is deterministic for the same canonical IP.
- Equivalent IPv6 textual forms produce the same hash.
- Different canonical IPs produce different hashes.
- Missing or invalid IP produces null.
- User-Agent and Referer are stored safely when present.
- UTM values are stored according to the schema.
- Oversized metadata is truncated, not rejected.
- Click persistence failure is logged and still redirects.
- No database details are exposed to the visitor.
- Malformed or unsafe destination URLs do not produce an unsafe redirect.
- Campaign/Offer relationships are loaded with bounded eager-loading queries.
- Postman/Newman collection validates the real public flow.
- New click tests and the full existing suite pass.
